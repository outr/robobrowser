# Native rendering implementation and acceptance

> **Architecture change — 2026-11-05:** #2 (one local JavaScript executor) is the sole browser path in 2.5.0-SNAPSHOT. DOM projection, pixel fallback, and dual-copy execution are removed. Earlier projection and Voidcraft remote-CDP evidence below is historical. See [current architecture](mirror/README.md); frontend disconnect still stops agent execution.

Native resource rendering is now the default. Website application code executes in the source browser; the viewer renders a scriptless DOM with local CSS, images, fonts, video/audio decoders, MediaSource buffers and canvas contexts. `?renderer=legacy` retains the earlier raster comparison renderer. Pixel view is an explicit user choice, never an automatic refresh or fallback.

## Local JavaScript execution experiment — 2026-11-03

The standalone demo's **Local script experiment** button opens `/execution` on the same port 8898. The main native DOM renderer remains unchanged. The experiment now offers two explicit modes:

- **Single local executor** (the experiment's default): the website runs only in the local frame. An authenticated server endpoint relays agent commands to that same document. Human and agent actions therefore share the same state and do not need a second execution of the action.
- **Dual-copy comparison**: the earlier experiment remains available to demonstrate independent state and duplicate writes when actions are broadcast to a local and a headless copy.

The single mode supports server-relayed `read`, `state`, `click`, `type`, `scroll`, and `eval` operations. `agentState` returns the current document epoch and connection status. An agent POST to `/execution/api` uses the existing demo Bearer authorization and an envelope such as `{"op":"agent","id":"SESSION","epoch":1,"requestId":"UNIQUE-ID","command":{"op":"click","selector":"#increment"}}`. Retries reuse the same request ID, epoch, and command. The server serializes delivery, retains 128 request results, and keeps up to 8,192 consumed request IDs for the session. An evicted result is reported as expired and its action is never replayed; exhausting the ID budget requires a new session. This is not durable exactly-once execution across server restarts. A changed command under the same retained ID is rejected. Page replacement cancels queued work and invalidates the old epoch. A disconnected viewer cannot execute commands. A local execution timeout reports an unknown outcome and blocks further mutations until a new document is attached; read/state remain available for inspection. The UI keeps its session ID across a shell refresh and reconnects with a new document epoch, avoiding an orphan experiment on each refresh.

Website scripts execute locally. HTML/CSS and selected runtime URL APIs route resource requests through separate per-session, per-upstream origins. Common URL attributes and reflected properties retain their original values for website code. This matters in practice: GitHub's player compares `getAttribute('src')` to its original asset URL before accepting metadata/canplay events. Merely changing the physical URL broke that check. This adapter is still not full browser-origin virtualization; outer HTML, unsupported APIs, and origin-sensitive application behavior can differ.

**GitHub media is now verified playing.** Its HEVC video failed in the local Chrome decoder. A bounded recovery path fetches the approved resource through the session network policy, probes it, and converts HEVC to H.264 in a network-isolated decoder sandbox. It accepts at most 16 MiB and two minutes per input, retains at most four conversions/32 MiB per session, supports byte ranges, and keeps the recovered resource on its original proxy origin with the upstream CORS policy. Website-visible source URLs remain stable. Other codec failures are reported rather than treated as HEVC. The public acceptance checks decoded-frame advancement, not just conversion success.

**Verified behavior:** an external HTTP agent and real mouse input act on the same fixture; one action sends one POST; sequential and concurrent retries do not repeat it; stale document actions and disconnected commands are rejected; uncertain execution does not get automatically replayed. Native input handlers observe agent edits. Local page focus requests do not steal the URL bar while it is being edited, and real page interaction releases that focus guard. The dual-copy regression still demonstrates two POSTs for one broadcast click, making the architectural difference measurable. See `mirror/target/single-execution/result.json` and `mirror/target/local-execution/result.json` for the measured runs and adjacent screenshots.

**Navigation follow-up:** entering another URL in single-executor mode preserves the existing session, mapped origins, and in-memory resource cookie jar. Mapped links and HTTP redirects can cross origins: the parent validates the destination against the server's registered session origins before connecting the new document. Page exit withdraws the old relay, and the replacement receives a new epoch. Shell refresh resumes the latest destination. Same-document history/hash changes update the saved URL without overwriting active address-bar edits. History API URL arguments are mapped, and relative runtime URLs follow the current route when the source has no explicit base URL. Acceptance covers navigation storage retention, stale commands, an unregistered-origin rejection, GitHub-to-Example-Domain link navigation, external agent reads after that transition, and shell refresh at the new origin. This does not intercept every navigation API: cancelable script-driven absolute navigation is now handled by the Navigation API bridge described below; noncancelable navigation and dynamically modified base elements still have compatibility limits. The later controlled popup, download and form coverage is recorded in EXECUTION_READINESS.md.

**Facebook request-metadata fix:** the resource gateway now preserves `Sec-Fetch-Mode`, `Sec-Fetch-User`, and browser client hints. Previously it stripped all `Sec-*` request headers. The former JDK HTTP connection also silently refused these headers, so the gateway now uses a per-session OkHttp transport through the same policy-enforcing SOCKS proxy, with automatic redirects and connection retries disabled. The controlled fixture asserts that navigation mode actually reaches the upstream server. A direct request comparison reproduced Facebook's error document with Chrome's user agent when navigation mode was absent, while retaining navigation mode returned the login page. Proxy-specific site/destination headers are still omitted rather than misrepresenting the iframe's origin as the upstream context. Public acceptance now includes Facebook's login controls and navigation away; this is not authenticated Facebook session acceptance. The earlier run reported React hydration error 418. The follow-up below fixes the inserted whitespace that caused that error and now requires a clean public-page startup.

**Material boundary:** this mode requires the local viewer to remain open. It is not the original architecture of an autonomous remote headless CDP browser continuing to execute when the viewer is gone. The DOM agent bridge uses synthetic events, not CDP trusted input, and does not implement the full production browser-tool protocol. Persistent CDP profiles, service workers, arbitrary worker/module URL construction, and transparent origin behavior remain outside this experiment. The local profile, cookie, navigation and WebSocket improvements below do not turn local execution into CDP execution. The gateway uses a separate original-origin cookie store, optionally persisted in an application-selected profile directory; it does not use the headless profile's authenticated CDP resource loader. Public pages and the controlled fixture are the current acceptance scope.

Control credentials stay in the parent UI, on a different origin from website scripts. Public-page proxy connections use the connection-time network policy to deny host-private destinations and DNS rebinding; only the controlled fixture session can reach its own demo origin. Converted media cannot be fetched from a different proxy origin to bypass its CORS boundary. Sessions and resource origins remain bounded. This is an experimental mode, not a production security acceptance claim.

Run `sbt 'mirror/Test/runMain spec.SingleExecutionAcceptance public' 'mirror/Test/runMain spec.LocalExecutionAcceptance public'`. The existing unit suite, address-bar and interaction regressions also passed after the relay/media work. The earlier packaged-client and two-hour endurance runs do not validate these changes. Demo ownership/token files now live in `.robobrowser-demo/` outside cleanable build output, preserving port 8898 and the existing authorized URL across builds.

## Local execution hardening — 2026-11-04

The latest follow-up addresses compatibility and state ownership in the single local executor. It does not replace the remote-executing native DOM mode.

- HTML serialization preserves whitespace. A controlled DOM-boundary regression and a public Facebook clean-startup assertion cover the hydration fix.
- Original-origin cookies now use explicit host-only/domain, path, expiry, Secure, HttpOnly, prefix and conservative schemeful SameSite rules. `document.cookie` reads and writes synchronize with the server store; scripts cannot expose or overwrite HttpOnly cookies. Fetch and XHR preserve credential modes and original response URLs. Controlled login, CSRF visibility, script-cookie propagation, logout, and credential omission are tested without signing into a third-party account. Script cookie operations currently use synchronous same-origin requests; their cost increases with network latency. Partitioned cookies are rejected rather than silently treated as unpartitioned cookies.
- Optional named profiles retain persistent cookies and stable mapped origins in an application-selected directory. Files are private to their owner and replaced atomically; an active profile has a filesystem lease. Browser localStorage/IndexedDB remain in the frontend browser under the stable profile origin. Session cookies expire when the profile closes. Reopening or restarting the service generates a new agent epoch, rejects stale commands, and restores the saved destination. This is a local-executor profile, not a Chrome user-data directory or a portable copy of frontend storage.
- The demo exposes a profile-name field. Blank means ephemeral. The managed demo stores named profiles under `.robobrowser-demo/profiles`. Other applications choose their own directory via `LocalExecutionExperiment`/`MirrorDemoServer`; there are no application-specific names or policies in the implementation. One active execution owns a named profile at a time.
- Cancelable document navigation is remapped through the Navigation API, including absolute script `location.href` changes. Cross-origin history traversal and browsers without that API are not claimed equivalent. POST forms and downloads are not replayed as GET navigation.
- Window WebSockets use an origin-owned server relay through the existing network policy and cookie store. Text, binary, Blob, protocol negotiation, handshake cookies, ordered send, close propagation and denied destinations have a real-browser echo-server regression. Limits: 16 channels per session, 1 MiB messages, 4 MiB receive/send queues, 256 queued received events, 45-second abandoned-channel expiry. The frontend transport is HTTP long polling; it is not a native end-to-end WebSocket and does not cover worker WebSockets or WebSocketStream. Transport failures close the channel without automatic replay.

The repeatable expanded gate is `scripts/execution-acceptance --public --endurance-seconds 600`; it includes file/upload, popup, form, iframe, media-retry and shadow-root workflows. Foundational test entrypoints include `ExecutionCookiesSpec`, `ExecutionProfilesSpec`, `ExecutionProfileAcceptance`, `ExecutionSocketAcceptance`, `SingleExecutionAcceptance public`, `LocalExecutionAcceptance public`, and `ExecutionEndurance 600 public`. The endurance report distinguishes event-to-next-animation-frame timing from physical input-to-display latency, and parent-viewer heap from total browser/process memory. See [EXECUTION_READINESS.md](EXECUTION_READINESS.md) for the remaining boundaries and release evidence.

## Pointer motion correction — 2026-11-03

Continuous viewer motion previously reached the source only over canvas/video elements. Ordinary DOM sent element-center hover events, losing the coordinates needed by document-level interactive graphics such as GitHub's mascot. The viewer now forwards exact viewport coordinates over projected DOM, retaining frame context and document generation, with one in-flight request and one latest pending sample. Center-hover dispatch is removed. Drag replay remains separate, and passive motion cannot take over another actor's lease.

The ordinary-DOM regression fails before the fix and passes afterward, including successive positions within the same element and no delayed center jump. Targeted validation also covers same-origin, cross-origin and nested-frame motion, agent lease preservation, clipboard/range/drag/closed-shadow interaction, and address-bar focus. Interaction and frame acceptance are now included in the standard acceptance script.

Public GitHub accepted 12 exact pointer targets, and the GitHub → Facebook → Wikipedia → GitHub navigation run completed with no viewer-reported errors. The managed port-8898 demo also passed a 90-sample continuous sweep, coalescing motion while delivering the exact final point, without raster fallback. Evidence: `mirror/target/pointer-verification/result.json`, `mirror/target/pointer-live/result.json`, and their adjacent logs/screenshots. The public probe timing records are polling-based source-arrival upper bounds, not input-to-display latency measurements.

This correction postdates the packaged-client and two-hour baseline below; that baseline does not verify these new viewer changes.

## Address-bar focus correction — 2026-11-03

User testing exposed focus theft that the previous acceptance did not cover. Snapshot reconciliation restored the source page's focused element even when the local user was editing the browser toolbar. Reconciliation now restores source focus only if that projected document owned local focus before the DOM update, protecting the toolbar and embedding application while retaining page focus through DOM changes.

The address-bar regression fails before the fix and passes afterward: real pointer focus, slow character-by-character input, repeated source focus changes, a tab-list refresh, and no keystrokes leaking into the source. Normal page focus, navigation, editing, interactions, and same-origin/cross-origin/nested-frame checks also pass. `scripts/native-acceptance` now includes the address-bar test. Evidence: `mirror/target/address-bar-acceptance/result.json` and `mirror/target/address-focus-verification.json`.

This viewer-only correction postdates the packaged-client and two-hour baseline below. Those runs are not claimed as verification of this change.

## Implementation

- [x] Progressive media and HTTP ranges through authenticated resource capabilities. The primary path copies bytes from the source browser's actual response with `Network.streamResourceContent`; a bounded source-browser fetch is the fallback. The service worker holds no source credentials. Its URLs belong to one viewer and document generation.
- [x] Native 2D canvas, Path2D, gradients and WebGL command replay. Complete clears can checkpoint drawing state; resource definitions and current frame state let a new viewer reconstruct the context. Website JavaScript is never evaluated in the viewer. Child documents retain `script-src 'none'`, including when the sandbox permits the browser to display native canvas pixels.
- [x] Dedicated classic/module worker OffscreenCanvas, including cross-origin frames, ImageBitmap texture inputs, original message payloads, reconnect, worker exit and one-shot completion before viewer attachment. Main-thread OffscreenCanvas is also captured.
- [x] MediaSource segment and operation journals on the host, with native SourceBuffer replay in the viewer. Includes append, remove, timestamp/window/mode changes, duration, completion, seeking and reconnect. Child-frame instrumentation runs before scripts in newly attached out-of-process frames.
- [x] Native play/pause/seek/rate/volume/mute propagation, source-driven changes, loop boundaries and read-only observers. Source-directed seeks retain their target until an appropriate local duration and, for MediaSource, buffered segments are available; clamped intermediate positions do not echo back to the source. Media command acknowledgments await completion and preserve the user gesture.
- [x] Native rendering by default, an explicit pixel view, and a retained legacy comparison mode. The source headless process in the demo and application client mutes its speaker output, independently of the page's media state.
- [x] Application-owned viewer routes, worker delivery, CSP and client work-lane integration. Browser/profile ownership stays in the application. No application-specific references occur in RoboBrowser production sources.
- [x] Controlled browser regressions, local and separate-JVM transports, native video/audio, segmented media, cross-origin frames, observer behavior, resource retirement, public-site navigation and timings.
- [x] Current media-clock fix validated in native application, backend-restart and Hero–Meg acceptance. The final executable passes the 34-check application probe plus native worker/media assertions in the actual embedded viewer, five restart checks and ten two-machine checks. Isolated Meg probe processes were confirmed stopped.
- [x] Final two-hour mounted-viewer endurance with three tabs, native video, worker canvases, shadow-root churn, tab switching and retained-heap checks. Passed 7,200 seconds, 13,806 rounds and 458 media-progress checks; retained source/viewer heap growth was 11.92/0.28 MiB, each below 64 MiB.
- [x] Updated managed demo on port 8898, with rendered desktop/narrow verification.

## Explicit limits

This is a working implementation with bounded support, not a claim that every browser API or every site is equivalent to a local browser.

- The viewer needs a secure origin (HTTPS or a browser-trusted localhost origin) for its media worker. Normal HTTP source pages remain supported.
- Direct media has a 512 MiB per-resource bound and bounded concurrent host caches. Cache-miss fallback may require an additional source-browser request; progressive startup is established for captured source responses.
- MediaSource journals have a 512 MiB serialized per-source bound, a 1 GiB process-wide bound and a command-count limit. They preserve reconnect history within those limits; this is not unlimited-duration live-stream retention. Playback still depends on the viewer's codecs.
- Canvas replay has byte, object and dimension budgets. Dedicated-worker and main-thread OffscreenCanvas are supported when instrumentation precedes context creation. SharedWorker/ServiceWorker canvas transport, contexts created before capture, and unsupported argument types are outside this tested support. Worker drawing retention is bounded to 256 canvases and 32 MiB per tab. Advanced WebGL workloads that cannot checkpoint retain bounded history and may reach the replay limit. No hidden raster loop substitutes for these cases.
- Bounded host HEVC recovery converts compatible finite files and gives the viewer a new media URL, avoiding Chromium's cached failed decode. It does not provide arbitrary codec transcoding or DRM support.
- DRM and WebRTC MediaStream/device forwarding are not implemented native transports. Capabilities report these limits. Pixel view does not imply audio/device/DRM forwarding.
- Source and viewer media clocks are approximately synchronized. Source-script interactions retain network latency; native video decoding and local editing feedback do not wait for each snapshot.

Historical completion claims in `DOM_MIRROR_PLAN.md` and the demonstrator report do not supersede these boundaries or constitute universal-site acceptance.

## Media clock follow-up — 2026-11-03

The stronger run stopped at 106 minutes on a single metadata-only decoder sample. A focused comparison confirmed that direct Chrome also reports this transient state at loop boundaries. Endurance now requires resumed decoded-frame progress within one second instead of treating that single sample as a stall, and records each recovery. The same comparison exposed a real 4x playback defect: unchanged source samples were treated as stationary times and caused repeated backward corrections. The viewer now preserves a source clock anchor across cached snapshots, advances its expected position at the playback rate and compares looping positions across the duration boundary. The accelerated regression rejects backward jumps outside actual loop boundaries. The full suite, accelerated loop regression, 34 native application checks, five restart checks and ten Hero–Meg checks pass on this clock fix. The final two-hour run passed 7,200 seconds, 13,806 rounds and 458 media-progress checks. It required advancing decoded frames/canvas epochs, selected-source visibility and empty viewer errors after tab switches. No decoder-transition recovery was needed in this final run. Production and endurance-test hashes match the frozen manifest; all 92 packaged classes and JavaScript resources match the tested build. Consolidated evidence: `mirror/target/native-full/worker-evidence.json` (status `passed`). The prior interrupted run remains under `worker-endurance-before-loop-readiness`.

## Worker rendering follow-up — 2026-11-03

Dedicated workers are initialized through CDP before their scripts execute. Transferred canvases keep a source-side identity; only allowlisted drawing commands and texture data reach the viewer. The application sees its original worker-message payload. Viewer scripts do not execute website or worker application code.

Tests cover classic and module workers, transfer-list and transfer-options forms, cross-origin frames, 2D/WebGL pixels, ImageBitmap textures, reconnect, source navigation and adopted tabs whose frame discovery was already enabled. Worker `close()` retains the final drawing, including one-shot workers that finish before the viewer attaches. Previously captured drawing state also survives external worker termination; work killed before capture cannot be reconstructed. Root navigation and tab disposal release retained worker drawings, and frame detachment retires descendant sessions.

Explicit pixel mode now survives refresh even when native rendering is the default; stale snapshot failure and switching back to native mode are covered by the mode regression.

The former application-build blocker was stale isolated fixture code against a changed Sigil snapshot. The fixture now uses a consistent current application/shared-API snapshot while retaining the browser acceptance probes. Normal application checkouts and running client services were not changed.

## Previous lifecycle hardening follow-up

The build blocker recorded in this historical section was resolved by the November 3 worker follow-up above.

The follow-up fixes detached MediaSource operations, stale errors after source replacement, and explicit seek targets that previously got lost during partial replay. Disposal cancels pending waits immediately, revokes the local object URL once and prevents further decoder writes. Removing and reinserting a video reconstructs its stream from the host journal. Host journals stop writing after a terminal error, release their reservation on file-open/write failure, and release stored bytes when child sessions detach. Empty polls avoid opening the journal file, and batch selection uses a view rather than copying the remaining history.

Canvas checkpoints now preserve the transforms used to construct each current-path segment. Replaying a translated path after a full clear or viewer reconnect no longer moves it to the origin.

Regression coverage includes deterministic cancellation/cursor/abort tests, actual video removal and reinsertion in main and cross-origin frames, journal byte accounting after navigation/frame removal, and transformed-path pixel checks. The 35-second follow-up timing trace recorded 1,053 native frames versus 1,055 direct frames, approximately 50 ms p95 frame-callback intervals for both, and no renderer playback-position writes. Evidence lives under `mirror/target/native-full/lifecycle-*`. The follow-up native executable built successfully, its packaged viewer resources match the checkout, and its startup/status smoke passed with an isolated configuration.
